# 一、研究目标

让 GUI Agent 在执行每一步之前，判断「直接执行 / 额外观察 / 额外推理 / 等待 / 问人」哪个更值得，在保证安全的前提下减少不必要的截图和推理，降低耗时，同时尽量提高成功率。安全相关的判断（拒绝、授权、审核）由独立的 Rust 门控 gui-gate 负责，agent 不能自己放行自己。

# 二、实验环境

- 评测：自建原生 OSWorld 环境（使用 OSWorld 的任务和评测器，没有虚拟机），**不是官方 OSWorld-Verified 成绩，不能直接和排行榜比较**。
- 主模型 deepseek-v4.1-flash，审核模型 decision-model-preview（System One）。Pi thinking 设为 medium，每题最多 100 轮，单题上限 3600 秒。问人策略设为自动拒绝（human=deny）。
- 只跑了门控一种配置，seed 0，**没有 direct 等对照组**。

# 三、主要结果

## 1. OSWorld-Verified 全量运行（gui-gate v0.9.9）

| 口径 | 成功 / 题数 | 成功率 | 95% 区间（Wilson） |
|---|---|---|---|
| 计划口径（361 题，infra 和缺失都算失败） | 185 / 361 | 51.25% | 46.1%–56.4% |
| 有效口径（去掉 28 个 infra 题和 1 个缺失题） | 185 / 332 | 55.72% | 50.3%–61.0% |
| 中途的部分结果（之前的基线） | 137 / 255 | 53.7% | — |

infra 失败共 28 个：环境准备失败 23、中转站出错 4、评测器出错 1。

## 2. 失败归类（147 个有效失败，每个只算一个主因）

| 主因 | 数量 |
|---|---|
| 答了 DONE 但结果不对（日志里分不清是模型能力、任务理解还是评测太严） | 96 |
| 超时或轮数用完（其中中转站挂起 5 个、check_done 卡死 1 个） | 20 |
| 被门拦下后放弃（9 个是门按设计要人确认、但评测设成自动拒绝；1 个是门的缺陷；1 个是环境差异） | 11 |
| 网站封锁了环境 | 6 |
| 门放行后执行失败 | 5 |
| 循环 | 3 |
| 没识别出不可行任务 | 3 |
| 可行任务却答 FAIL | 3 |

根据这份归类，修了门的 2 个通用缺陷：脚本里的 `str.replace` 被当成移动文件（40 次误拦），以及 Chromium 的子菜单入口被当成分享动作。可能会拟合到这 361 题的改动都没有做。

## 3. 价值模型离线分析（用 gui-pi3 的日志）

- 旧报告的 AUC 0.626 偏低，主要是把终端命令和 GUI 动作混在一起算了。命令实际成功率约 93%，预测却只有约 26%。

| 预测器（GUI 动作，7225 行） | AUC | ECE |
|---|---|---|
| 内置预测器 | 0.694 | 0.043 |
| 原特征重新训练（按应用领域留出） | 0.773 | 0.024 |
| 新加 click/scroll 特征 | 0.770 | 0.028 |

- 新特征带来的提升是 −0.003（95% 区间 −0.018 到 +0.012），**没有可靠收益**。
- 实测耗时：look_full 平均 26.4 秒（中位数 9.8 秒，原先假设是 9 秒）；review 15.8 秒（原先假设 3 秒）；look_light 8.0 秒；wait 1.2 秒；check 0.3 秒。这些是用相邻动作的间隔估出来的，偏粗。
- 日志里只有 direct 和 wait 两种处理样本足够；look、review、check、heal 的效果**没法从日志估出来**。
- 只介入 5% 的步骤时，事后筛选能标出约 43% 的历史失败。这**不等于**能避免 43% 的失败。

## 4. 其它实验

- 截图格式：全尺寸 JPEG q60 和 PNG 准确率一样，首 token 快约 3 倍。已定为默认格式，不缩小图片。
- 安全回归：5 类安全问题（表单冲突、跨任务复用批准、只读工具写盘、等人时撤销请求、unknown 后重发）各写了真门测试。修复前 9 项失败，修复后全部通过。gui-gate 测试：cargo 166 项、Python 342 项全过。
- 桌面版真机测试：在 gui-pi5 上用真模型（qwen3.8-flash）测 0.3.0。安装到运行的整个流程走通，发现 11 个问题（B1–B11），修完后复测两轮全部通过。Windows 和 macOS 版只在 GitHub CI 上做过冒烟测试，**还没上真机，也没用真模型测**。

# 四、结论

1. 门控版本在自建环境里的有效成功率是 55.72%。没有对照组，所以**还不能证明门控本身提升了成功率**。
2. 现在的预测器能预测一部分「执行会失败」，但还**没有证明**它能预测「多观察一次或多推理一次能带来多少收益」。真正的瓶颈在数据：处理前和处理后的特征混在一起，标签归属也不严格。
3. 安全协议和问人流程已经有回归测试覆盖。真正的隔离仍然要靠操作系统层面来做。

# 五、下一步

- 正在做 gui-gate v0.10.3（最后一个独立版本）和桌面版 0.3.2：统一派发检查、unknown 账本、批准绑定业务状态、记录处理前特征、分层标签。
- 两个小规模在线实验已经设计好，还没跑：
  - 策略试点：12 题 × 3 个条件 × 3 个 seed，共 108 次运行。
  - 增量试点：从 24 个检查点分支，比较 direct、look_full 和等时等待，共 216 条分支。
- 先测出增量收益，再决定是否在线上启用价值模型。
